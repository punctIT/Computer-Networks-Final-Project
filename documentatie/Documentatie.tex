\begin{abstract}
NetworkDevicesMonitor este o platforma software completa pentru monitorizarea si analiza infrastructurii IT, integrand protocoale standardizate (Syslog) cu agenti personalizati pentru colectarea telemetriei. Arhitectura multi-threaded implementeaza pattern-uri avansate (Producer-Consumer, Thread-Safe Queues) si ofera o interfata grafica asincrona Qt6 cu dashboard-uri interactive, vizualizari in timp real, sistem de alertare automata si filtrare avansata. Proiectul demonstreaza aplicarea conceptelor de retele, concurenta, baze de date si design UI/UX profesional, incluzand functionalitati complete de securitate prin whitelist/blacklist, management alerte personalizate si filtre dinamice.
\end{abstract}

\section{Introducere}

\subsection{Viziunea Generala și Motivatie}
in infrastructurile IT moderne, echipamentele de retea (routere, switch-uri, firewall-uri) si statiile de lucru genereaza volume masive de date sub forma de log-uri si metrici. Monitorizarea manuala devine rapid impracticabila. Lipsa unui sistem centralizat conduce inevitabil la:
\begin{itemize}[itemsep=0em]
    \item Pierderea evenimentelor critice de securitate.
    \item Dificultati majore in diagnosticarea problemelor de performanta.
    \item Lipsa vizibilitatii centralizate asupra infrastructurii.
    \item Timp de raspuns crescut la incidente.
    \item Absenta filtrarii inteligente a datelor relevante (zgomot informational).
    \item Management ineficient al alertelor si notificarilor.
\end{itemize}

\subsection{Obiectivele Proiectului}
NetworkDevicesMonitor a fost dezvoltat pentru a adresa aceste provocari prin urmatoarele obiective tehnice specifice:

\begin{enumerate}
    \item \textbf{Colectare Hibrida și Flexibila:} 
    \begin{itemize}
        \item Integrarea Syslog (RFC 5424) pe portul 1514 pentru echipamente standard.
        \item Implementarea de Agenti custom pe portul 9000 pentru metrici detaliate (CPU, RAM, disk).
        \item Control total prin protocolul JUNK pe portul 8080.
    \end{itemize}
    
    \item \textbf{Procesare Concurenta Performanta:}
    \begin{itemize}
        \item Utilizarea I/O Multiplexing cu \texttt{poll()} pentru receptie non-blocanta a datelor.
        \item Implementarea Thread-Safe Queues pentru decuplarea totala a ingestiei de procesare.
        \item Folosirea de Worker threads pentru parsing si analiza paralela.
        \item Sincronizare prin Shared mutex pentru operatiuni concurrent read-heavy.
    \end{itemize}
    
    \item \textbf{Securitate prin Filtrare Multi-Nivel:}
    \begin{itemize}
        \item Source Manager dedicat cu Whitelist/Blacklist IP-uri.
        \item Validare automata a surselor inainte de alocarea resurselor de procesare.
        \item Izolare trafic malitios si unknown sources.
        \item Filtre personalizate pe tip, mesaj si alerte custom.
    \end{itemize}
    
    \item \textbf{Vizualizare si UX Avansat:}
    \begin{itemize}
        \item Dashboard asincron Qt6 cu actualizari in timp real.
        \item Grafice interactive (Donut Charts, Line Charts) și sistem de alertare pop-up.
    \end{itemize}
\end{enumerate}

\section{Tehnologii Aplicate}

Selectia tehnologiilor a fost motivata de nevoia de performanta, control asupra memoriei si interfata moderna.

\subsection{C++23 (Backend) și Concurenta}
Am ales C++23 pentru a beneficia de noile standarde de siguranta și viteza. Arhitectura se bazeaza pe:
\begin{itemize}
    \item \textbf{Multi-threading:} Am folosit pattern-ul \textbf{Producer-Consumer} pentru a gestiona fluxurile de date. Firele de executie sunt gestionate manual pentru un control fin.
    \item \textbf{Sincronizare:} Accesul la structurile de date partajate (liste de loguri, cozi) este protejat prin \texttt{std::mutex} și \texttt{std::shared\_mutex}, asigurand integritatea datelor fara a bloca excesiv citirile.
\end{itemize}

\subsection{Protocolul TCP}
Am optat exclusiv pentru TCP (Transmission Control Protocol) pentru toate cele 3 canale (Syslog, Agenti, Admin) din urmatoarele motive:
\begin{itemize}
    \item Fiabilitate: Este critic ca log-urile de securitate și alertele sa ajunga la destinatie fara pierderi.
    \item Ordinea pachetelor: Cronologia evenimentelor este esentiala in debugging.
\end{itemize}

\subsection{SQLite3 (Stocare)}
Baza de date functioneaza in modul WAL (Write-Ahead Logging). Aceasta este o componenta critica pentru performanta intr-un mediu multithreaded, permitand operatiuni de citire și scriere simultane. Tabelele principale includ: \texttt{logs}, \texttt{agents\_metrics}, \texttt{whitelist}, \texttt{blacklist}, \texttt{alerts} și tabele pentru filtre.

\subsection{Qt6 (Interfata Grafica)}
Framework-ul Qt6 a fost ales pentru sistemul sau de Signals \& Slots, care permite actualizarea interfetei grafice asincron, fara a bloca thread-ul principal (UI thread) atunci cand sosesc pachete de la server.

\subsection{Server Backend}
Responsabil pentru logica de business și persistenta datelor.
\begin{itemize}
    \item \textbf{LogPipeline:} Orchestreaza intregul flux de date.
    \item \textbf{SyslogReceiver \& AgentsReceiver:} Module de receptie care pun datele in cozi thread-safe.
    \item \textbf{SourceManager:} Gestioneaza securitatea (Whitelist/Blacklist).
    \item \textbf{DataProcessor:} Preia datele din cozi, le parseaza și le trimite la baza de date.
    \item \textbf{AlertsManager:} Analizeaza datele procesate pentru a detecta pattern-uri suspecte (consum mare de resurse, cuvinte cheie interzise).
    \item \textbf{FiltresManager:} Aplica regulile de filtrare definite de utilizator (pe tip sau mesaj).
\end{itemize}

\subsection{Client GUI}
O aplicatie desktop structurata pe pagini, cu lifecycle management (hooks de \texttt{on\_enter} și \texttt{on\_exit}).
\textbf{Pagini implementate:}
\begin{itemize}
    \item \textbf{ConnectPage \& LoginPage:} Gestionarea conexiunii și autentificarii.
    \item \textbf{HomePage \& DashboardPage:} Vizualizare date (Syslog Dashboard, Agents Dashboard, Unknown Data).
    \item \textbf{SecurityPage:} Management vizual pentru Whitelist și Blacklist.
    \item \textbf{AlertsPage \& FiltresPage:} Configurare alerte și filtre.
\end{itemize}

\section{Protocolul de Comunicare}

Sistemul utilizeaza trei protocoale distincte, adaptate fiecarui tip de trafic.

\subsection{A. Port 1514 - Syslog (RFC 5424)}
\textbf{Fluxul de procesare:}
\begin{enumerate}
    \item \textbf{Receptie:} Thread cu \texttt{poll()} monitorizeaza socket-ul.
    \item \textbf{Validare:} IP-ul este verificat in Whitelist/Blacklist.
    \item \textbf{Parsare:} Se extrag campurile standard (PRI, Timestamp, Hostname, AppName, Message).
    \item \textbf{Filtrare \& Analiza:} Se aplica filtrele și se verifica de alerte.
\end{enumerate}

\subsection{B. Port 9000 - Agenti}
Protocol binar/JSON optimizat:
\begin{itemize}
    \item Header (4 bytes): Lungimea payload-ului.
    \item Payload: JSON cu metrici (\texttt{cpu}, \texttt{ram}, \texttt{disk}).
\end{itemize}

\subsection{C. Port 8080 - Admin API (Protocol JUNK)}
Protocolul custom JUNK (Just Useful Notation Kinda) este folosit pentru comunicarea Client-Server.
Format: \texttt{Length(4 bytes) + key:\{value\};key2:\{value2\};}

\section{Scenarii de Utilizare}

\subsection{Scenarii de Succes}

\subsubsection{Scenariu 1: Monitorizare Agent in Timp Real}
\textbf{Context:} Un server de baze de date PostgreSQL trimite metrici la interval de 5 secunde.
\begin{enumerate}
    \item Agent Python colecteaza date de sistem (CPU, RAM, Disk).
    \item Pachet JSON trimis pe port 9000 cu header binar.
    \item Server primeste, valideaza IP in whitelist via SourceManager.
    \item DataProcessor extrage metrici, insert in \texttt{agents\_metrics}.
    \item Clientul primeste signal \texttt{AgentDataUpdated}.
    \item Dashboard actualizeaza graficul CPU/RAM automat fara refresh manual.
\end{enumerate}
\textbf{Rezultat:} Administratorul vizualizeaza in sub 3 secunde creșterea CPU la 92\%.

\subsubsection{Scenariu 2: Onboarding Echipament Nou}
\textbf{Flow:}
\begin{enumerate}
    \item Admin acceseaza SecurityPage $\rightarrow$ Whitelist tab.
    \item Click "Add Source", completeaza in popup IP-ul si Hostname-ul.
    \item Click "Add" $\rightarrow$ cerere JUNK trimisa la server.
    \item SourceManager insereaza in DB și actualizeaza hash map-ul in-memory.
    \item Switch-ul incepe sa trimita syslog pe 1514. IP-ul este verificat $\rightarrow$ ACCEPTED.
    \item Procesat imediat, apare in Syslog Dashboard.
\end{enumerate}
\textbf{Rezultat:} Zero downtime, vizibilitate instantanee.

\subsubsection{Scenariu 3: Configurare Filtre Custom (Reducere Zgomot)}
\textbf{Context:} Admin vrea sa ignore log-uri verbose de la servere web (HTTP 200 OK).
\begin{enumerate}
    \item Acceseaza FiltresPage $\rightarrow$ Message Filters tab.
    \item Click "Add Message Filter" și introduce keyword: "HTTP 200".
    \item Server adauga in \texttt{filtres\_message} table și reincarca cache-ul.
    \item Log-urile urmatoare cu "HTTP 200" sunt filtrate automat.
\end{enumerate}
\textbf{Rezultat:} Dashboard curat, focus doar pe erori.

\subsubsection{Scenariu 4: Alerta Personalizata pe Keyword}
\textbf{Context:} Admin vrea notificare instant la orice mesaj continand "OutOfMemory".
\begin{enumerate}
    \item FiltresPage $\rightarrow$ Custom Alerts $\rightarrow$ Add "OutOfMemory".
    \item Un serviciu Java crasheaza cu "java.lang.OutOfMemoryError".
    \item Log syslog primit, DataProcessor face match pe keyword.
    \item AlertsManager creeaza alerta CRITICAL.
    \item Popup instant la client: "OutOfMemory error detected on app-server-03".
\end{enumerate}

\subsection{Scenarii de Eșec (Recuperare și Stabilitate)}

\subsubsection{Scenariu 5: Trafic Malitios Blocat}
\textbf{Context:} Botnet incearca flood de date false pe port 1514.
\begin{enumerate}
    \item 1000 de pachete/sec de pe IP 198.51.100.10 (care este in blacklist).
    \item SyslogReceiver detecteaza conexiune in \texttt{accept()}.
    \item SourceManager verifica: \texttt{check\_ip\_blacklist()} $\rightarrow$ \texttt{true}.
    \item Socket inchis imediat cu \texttt{close(client\_fd)}, zero procesare.
    \item Log intern in \texttt{security\_events}.
\end{enumerate}
\textbf{Rezultat:} Zero impact pe performanta, CPU usage normal.

\subsubsection{Scenariu 6: Pachet Corupt Primit}
\textbf{Context:} Serverul primeste un pachet invalid care nu e in formatul JUNK.
\begin{enumerate}
    \item RequestHandler logheaza eroarea și trimite raspuns de eroare.
\end{enumerate}
\textbf{Rezultat:} Server nu crasheaza (segmentation fault evitat), conexiune mentinuta.

\subsubsection{Scenariu 7: Token invalid}
\begin{enumerate}
    \item Client incearca sa ceara logs cu token invalid/nerecunoscut.
    \item SessionManager verifica: token nu exista in hash map.
    \item Raspuns: eroare, sesiune invalida.
\end{enumerate}

\section{Concluzii}

Acest proiect a fost, inainte de toate, o experienta de invatare foarte utila. Daca la inceput totul era doar o schita, acum am un server functional (cu Syslog si Agenti) si un client care chiar comunica intre ei.
Nu a fost doar despre scris cod, ci despre a intelege cum se leaga lucrurile in prezent:
\begin{itemize}
    \item \textbf{C++23:} Am profitat de ocazie sa explorez noutatile din noul standard pentru a scrie codul mai modern.
    \item \textbf{Concurenta:} Am invatat sa gestionez mai bine firele de executie și sa evit race conditions folosind mutex-uri partajate.
    \item \textbf{Arhitectura:} Am pus mare pret pe modularitate. Faptul ca am impartit totul pe clase si module (SourceManager, AlertsManager, etc.) m-a ajutat enorm sa nu ma pierd in detalii pe masura ce proiectul crestea.
\end{itemize}

\subsection{imbunatatiri Viitoare}
Sunt constient ca proiectul nu este perfect. Daca as mai avea timp, urmatoarele aspecte ar putea fi optimizate:
\begin{enumerate}
    \item \textbf{Securitate Transport:} Implementarea SSL/TLS pentru criptarea pachetelor JUNK, care momentan circula in plain-text.
    \item \textbf{Export Rapoarte:} Adaugarea posibilitatii de a exporta datele din tabele in format CSV sau PDF.
\end{enumerate}

Totusi, pentru stadiul actual, consider ca a iesit un proiect bun, stabil si, cel mai important, usor de inteles datorita structurii sale ordonate. A fost o provocare care mi-a aratat exact unde mai am de lucrat, dar si cat de mult am progresat.
