\begin{abstract}
NetworkDevicesMonitor este o platformă software completă pentru monitorizarea și analiza infrastructurii IT, integrând protocoale standardizate (Syslog) cu agenți personalizați pentru colectarea telemetriei. Arhitectura multi-threaded implementează pattern-uri avansate (Producer-Consumer, Thread-Safe Queues) și oferă o interfață grafică asincronă Qt6 cu dashboard-uri interactive, visualizări în timp real și sistem de alertare automată.  Proiectul demonstrează aplicarea conceptelor de rețele, concurență, baze de date și design UI/UX profesional.
\end{abstract}

\section{Introducere și Context}

\subsection{Motivație}
În infrastructurile IT moderne, echipamentele de rețea (routere, switch-uri, firewall-uri) și stațiile de lucru generează volume masive de date sub formă de log-uri și metrici. Monitorizarea manuală devine rapid impracticabilă, conducând la: 
\begin{itemize}
    \setlength\itemsep{0em}
    \item Pierderea evenimentelor critice de securitate
    \item Dificultăți în diagnosticarea problemelor de performanță
    \item Lipsa vizibilității centralizate asupra infrastructurii
    \item Timp de răspuns crescut la incidente
\end{itemize}

\subsection{Obiective Tehnice}
NetworkDevicesMonitor adresează aceste provocări prin: 

\begin{enumerate}
    \item \textbf{Colectare Hibridă: } 
    \begin{itemize}
        \item Syslog (RFC 5424) pe portul 1514 pentru echipamente standard
        \item Agenți custom pe portul 9000 pentru metrici detaliate (CPU, RAM, disk)
    \end{itemize}
    
    \item \textbf{Procesare Concurentă Performantă:}
    \begin{itemize}
        \item I/O Multiplexing cu \texttt{poll()} pentru recepție non-blocantă
        \item Thread-Safe Queues pentru decuplarea ingestiei de procesare
        \item Worker threads pentru parsing și analiză paralelă
    \end{itemize}
    
    \item \textbf{Securitate prin Filtrare:}
    \begin{itemize}
        \item Source Manager cu Whitelist/Blacklist IP-uri
        \item Validare automată a surselor înainte de procesare
        \item Izolare trafic malițios
    \end{itemize}
    
    \item \textbf{Vizualizare și UX:}
    \begin{itemize}
        \item Dashboard asincron Qt6 cu actualizări în timp real
        \item Grafice interactive (Donut Charts, Line Charts)
        \item Sistem de alertare pop-up pentru evenimente critice
    \end{itemize}
\end{enumerate}

\subsection{Pipeline-ul de Date}

\subsubsection{Port 1514 - Syslog Receiver}
\textbf{Fluxul de procesare:}

\begin{enumerate}
    \item \textbf{Recepție: } Thread dedicat cu \texttt{poll()} monitorizează socket-ul
    \item \textbf{Parsare:} Extragere câmpuri conform RFC 5424:
    \begin{itemize}
        \item PRI (Priority = Facility × 8 + Severity)
        \item Timestamp
        \item Hostname
        \item Source (proces/serviciu)
        \item Message
    \end{itemize}
    \item \textbf{Validare:} Source Manager verifică IP-ul în Whitelist/Blacklist
    \item \textbf{Stocare:} Insert în tabela \texttt{logs} sau \texttt{unknown\_log}
\end{enumerate}

\textbf{Exemplu mesaj Syslog procesat:}
\begin{lstlisting}
<13>Nov 27 15:37:44 server02 sshd[3452]: 
  Accepted password for user_valid from 192.168.2.5
\end{lstlisting}

\subsubsection{Port 9000 - Agent Receiver}
\textbf{Protocol de comunicare:}
\begin{itemize}
    \item Header binar:  4 bytes (uint32) = lungime payload
    \item Payload JSON cu metrici: 
\end{itemize}

\begin{lstlisting}[language=Python]
{
  "hostname": "workstation-01",
  "ip_address": "192.168.1.10",
  "os_info": "Linux",
  "cpu_load": 45.2,
  "ram_usage": 68.5,
  "disk_usage": 72.1,
  "status_message": "OK",
  "active_user":  "admin"

\subsubsection{Port 8080 - Admin API}
\textbf{Protocol custom JUNK (Just Useful Notation Kinda):}

Format:  \texttt{key:\{value\};key2:\{value2\};}

\textbf{Exemplu cerere login:}
\begin{lstlisting}
type:{login};username:{admin};password:{pass123};
\end{lstlisting}

\textbf{Exemplu răspuns:}
\begin{lstlisting}
status:{TRUE};type:{login};content:{token_abc123xyz};
\end{lstlisting}

\subsection{Server:  Concurență și Thread Safety}

\subsubsection{Thread-Safe Queue Implementation}
Pattern Producer-Consumer pentru decuplarea I/O de procesare:

\begin{lstlisting}
template<class T>
class ThreadSafeQueue {
    std::queue<T> queue;
    std::mutex _mutex;
public:
    void push(T value) {
        std::lock_guard<std::mutex> lock(_mutex);
        this->queue.push(value);
    }
    
    std:: expected<T, std::string> pop() {
        std::lock_guard<std::mutex> lock(_mutex);
        if(queue.empty()) 
            return std::unexpected("Empty queue");
        auto value = queue.front();
        queue.pop();
        return value;
    }
};
\end{lstlisting}

\subsubsection{Source Manager - Sistem de Securitate}
\textbf{Operațiuni principale:}

\begin{lstlisting}
class SourceManager {
    std::shared_mutex _mutex;
    std::unordered_map<std::string, std::string> 
        whitelist_source; // IP -> Hostname
    std::unordered_set<std::string> blacklist_source;
    
    std::optional<std::string> 
    check_ip_whitelist(std::string ip) {
        std::shared_lock lock(_mutex);
        if(whitelist_source.contains(ip))
            return whitelist_source[ip];
        return std::nullopt;
    }
    
    bool check_ip_blacklist(std:: string ip) {
        std::shared_lock lock(_mutex);
        return blacklist_source.contains(ip);
    }
};
\end{lstlisting}

\section{Scenarii de Utilizare}

\subsection{Scenarii de Succes}

\subsubsection{Scenario 1: Monitorizare Agent în Timp Real}
\textbf{Context:} Un server de baze de date PostgreSQL trimite metrici la interval de 5 secunde.

\textbf{Flow:}
\begin{enumerate}
    \item Agent Python colectează date cu \texttt{psutil}
    \item Pachet JSON trimis pe port 9000
    \item Server primește, validează IP în whitelist
    \item DataProcessor extrage metrici, insert în \texttt{agents\_metrics}
    \item Client primește signal \texttt{AgentDataUpdated}
    \item Dashboard actualizează grafic CPU/RAM automat
\end{enumerate}

\textbf{Rezultat:} Administrator vizualizează în sub 1 secundă creșterea CPU la 92\%, investigare preventivă. 

\subsubsection{Scenario 2: Detectare Tentativă de Intruziune}
\textbf{Context:} Atacator încearcă brute-force SSH pe server de producție.

\textbf{Flow:}
\begin{enumerate}
    \item Router trimite 10 log-uri consecutive: 
    \begin{lstlisting}[language=bash]
<13>sshd:  Failed password for root from 203.0.113.42
    \end{lstlisting}
    \item DataProcessor detectează pattern (10 eșecuri în 60 sec)
    \item AlertsManager creează alertă cu severitate HIGH
    \item Client primește notificare via \texttt{UpdateAlertsPopup} signal
    \item Pop-up roșu apare în colț:  "SSH Brute Force Detected!"
    \item Admin deschide SecurityPage, adaugă 203.0.113.42 în blacklist
\end{enumerate}

\textbf{Rezultat:} Bloc automat, tentative ulterioare respinse la nivel de Source Manager.

\subsubsection{Scenario 3: Onboarding Echipament Nou}
\textbf{Context:} Instalare switch Cisco nou în rețea.

\textbf{Flow:}
\begin{enumerate}
    \item Admin accesează SecurityPage → Whitelist tab
    \item Click "Add Source", completează: 
    \begin{itemize}
        \item IP: 192.168.10.50
        \item Hostname: switch-floor2
    \end{itemize}
    \item Click "Save" → cerere trimisă la server
    \item SourceManager inserează în DB + hash map in-memory
    \item Switch-ul trimite primul syslog
    \item Procesat imediat, apare în Syslog Dashboard cu label "switch-floor2"
\end{enumerate}

\subsection{Scenarii de Eșec și Recuperare}

\subsubsection{Scenario 4: Trafic Malițios Blocat}
\textbf{Context:} Botnet încearcă flood de date false pe port 1514.

\textbf{Flow:}
\begin{enumerate}
    \item 1000 de pachete/sec de pe IP 198.51.100.10 (blacklist)
    \item SyslogReceiver detectează conexiune
    \item Source Manager verifică:  \texttt{check\_ip\_blacklist()} → \texttt{true}
    \item Socket închis imediat, zero processing
    \item Log în \texttt{security\_events}:  "Blocked blacklist IP attempt"
\end{enumerate}

\textbf{Rezultat:} Zero impact pe performanță, CPU usage normal.

\subsubsection{Scenario 5: Pachet Corupt Primit}
\textbf{Context:} Eroare de rețea corupe header-ul unui pachet JUNK.

\textbf{Flow:}
\begin{enumerate}
    \item Client trimite pachet cu lungime incorectă în header
    \item Server citește 4 bytes:  \texttt{length = 999999} (invalid)
    \item Buffer allocation failsafe:  maxim 64KB
    \item \texttt{JUNK:: deserialize()} returnează \texttt{std::unexpected}
    \item RequestHandler log eroare, trimite: 
    \begin{lstlisting}
status:{FALSE};type:{error};content:{Invalid format};
    \end{lstlisting}
    \item Client afișează mesaj:  "Request failed, retry"
\end{enumerate}

\textbf{Rezultat:} Server nu crashează, conexiune menținută.

\subsubsection{Scenario 6: Token Expirat}
\textbf{Context:} Admin lasă aplicația deschisă 24h, sesiune expirată.

\textbf{Flow:}
\begin{enumerate}
    \item Client încearcă să ceară logs cu token vechi
    \item SessionManager verifică:  token nu mai există în hash map
    \item Răspuns: \texttt{status:\{FALSE\};content:\{Session expired\};}
    \item Client primește signal, PageManager execută: 
    \begin{lstlisting}
    page_manager->change_page(LOGIN_PAGE);
    \end{lstlisting}
    \item User redirectat automat la login, fără pierdere date locale
\end{enumerate}

\subsubsection{Faza 1: Securitate (Prioritate Înaltă)}

    \item Implementare TLS 1.3 pentru toate comunicațiile
    \item Password hashing cu Argon2id
    \item Certificate-based authentication pentru agenți
    \item Audit logging pentru toate operațiunile admin

\subsubsection{Faza 2: Features Avansate}
\begin{itemize}

\subsubsection{Faza 3: Scalabilitate Enterprise}
\begin{itemize}
    \item Migration la PostgreSQL pentru volume mari (>10M logs/zi)
    \item Distributed deployment cu load balancing (HAProxy)
    \item Kubernetes manifests pentru orchestration
    \item Prometheus/Grafana integration pentru self-monitoring
\end{itemize}

\subsection{Lecții Învățate}

\begin{enumerate}
    \item \textbf{Thread Safety is Hard:} Debugging race conditions a necesitat extensive logging și Valgrind/Helgrind analysis
    \item \textbf{Protocol Design:} JUNK protocol s-a dovedit simplu dar eficient, viitor:  Protobuf pentru performance
    \item \textbf{Qt Signals:} Paradigma event-driven simplifică dramatic UI asincron
    \item \textbf{SQLite Limitations:} WAL mode excelent pentru citiri concurente, dar bottleneck la >1000 write/sec
\end{enumerate}

NetworkDevicesMonitor poate fi adaptat pentru:
\begin{itemize}
    \item \textbf{SMEs:} Monitoring infrastructură mici/medii companii
    \item \textbf{Datacenters:} Centralizare logs pentru sute de servere
    \item \textbf{IoT:} Colectare telemetrie de la device-uri embedded
    \item \textbf{Security Operations Centers:} SIEM lightweight pentru incident response
\end{itemize}
